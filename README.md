# Internship Platform

A free online internship platform for engineering students. Students sign up with an email code, pick a domain, complete its tasks, build a project, get it verified, and can then optionally buy a verified certificate for ₹50 by manual UPI payment. There is **no payment gateway**.

The brand name (`Zevpra Intern`) is driven by one config (`src/lib/config/branding.ts` + env). Change `COMPANY_NAME` (or the `brand.company_name` setting in the admin panel) once and the whole app follows.

## The flow (all enforced on the server)

```
Sign up / log in (email OTP)
  -> choose a domain and apply            (admin approves, or auto-approve setting)
  -> tasks for that domain                (mentor reviews; resubmit while attempts remain)
  -> project step UNLOCKS when required tasks are approved
  -> pick ONE project, submit GitHub repo (locked after first submission)
  -> admin verifies the project           (approval = internship complete = certificate-eligible)
  -> pay the certificate fee by UPI, upload screenshot + UTR   (status: UNDER REVIEW)
  -> admin verifies the payment           (approval creates the certificate in one transaction)
  -> PDF with QR is generated by a background job, shown in the portal
  -> anyone can verify it at /verify-certificate/<id>
```

Submitting a screenshot and UTR **never** creates a certificate. Only a person with the `payments.review` permission can approve it.

## Stack

Next.js 15 (App Router, React 19, TypeScript strict) · Tailwind CSS 4 · Prisma 7 + PostgreSQL · Redis (rate limits) · Three.js / React Three Fiber · Motion · pdf-lib + qrcode · Zod · Vitest + Playwright (tests).

## Quick start

```bash
npm install
cp .env.example .env.local          # then fill it in (see docs/DEPLOYMENT.md)
npm run db:generate
npm run db:push                     # or: npm run db:migrate -- --name init
npm run db:seed                     # roles, permissions, domains, settings, FAQs, templates, super admin
npm run db:seed:demo                # OPTIONAL sample internship, tasks and projects (never in production)
npm run dev
```

In `.env.local` set `SEED_SUPER_ADMIN_EMAIL`, `SEED_SUPER_ADMIN_NAME` and `SEED_SUPER_ADMIN_PASSWORD` **once** (dotenv keeps the first value if a key appears twice) before `npm run db:seed`.

Requirements: Node 20+, PostgreSQL 14+, Redis 6+.

### Useful scripts

| Command | What it does |
|---|---|
| `npm run worker` | Background job worker (emails, certificate PDFs, repo checks). Run beside the web app. |
| `npm run retention` | Daily retention sweep (email_logs 30d, notifications 90d, sessions 7d, OTP 1d, background_jobs 7d, security_events 180d; audit_logs skipped). |
| `npm run dev:otp -- you@mail.com [PURPOSE]` | **Dev only.** Prints the latest one-time code (the console email driver never logs codes). |
| `npm run email:logs -- [limit]` | Read-only email delivery audit from `email_logs`. Point `DATABASE_URL` at production to see why a code never arrived. |
| `npm test` | Unit tests. |
| `npm run test:integration` | Full flow + security tests against a real database and Redis. |
| `npm run build` | Production build. |

## Where things live

```
src/app/            routes: (public) site, student/(portal), admin/(panel), api/
src/components/     3d/ (WebGL world), motion/, home/, dashboard/, forms/, layout/
src/server/         services/ (business rules), jobs/ (queue + runner), queries/
src/lib/            auth, api (errors, handler, CSRF), redis, email, storage, security, validation
prisma/             schema.prisma, seed.ts, seed-demo.ts
tests/              unit/ and integration/
docs/               FRONTEND.md, SECURITY_AUDIT.md, DEPLOYMENT.md
```

Business logic lives in `src/server/services`; pages and API routes are thin. Every mutation re-checks authorisation there.

## Roles

| Role | Can |
|---|---|
| STUDENT | Their own profile, applications, tasks, project, payment proof, certificate. |
| MENTOR | View students, review task submissions, leave project feedback, announcements. |
| ADMIN | Everything operational: approve applications, **verify projects**, **verify payments**, content, exports. |
| SUPER_ADMIN | Also: payment settings, UPI/QR, certificate revocation, creating and managing admins. |

The permission matrix is seeded into the database and checked server-side by `requireStaff(permission)`.

## Testing

```bash
npm test                                   # fast, no services needed
export DATABASE_URL=postgresql://...       # a migrated + seeded database
npm run test:integration
```

The integration suite covers the whole journey and the abuse cases: cross-student access (IDOR), duplicate UTR, double payment approval racing two admins, fake payment, SQL injection, CSV injection, MIME spoofing, CSRF origin checks, RBAC, rate limits and job claiming.
